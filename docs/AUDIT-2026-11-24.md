# TimberTally code audit — 2026-11-24

Branch `forestscribe-features`, working tree as of today (uncommitted work included). Read-only audit; nothing else was changed.
Calc spot-checks were run with a node/vm harness over `forestry-data.js` + `forestry-calc.js`.

Scope note: storage, calc, CSV import/export, service worker, XSS sinks and tour targets were checked in depth. Layout at 375px and dark mode were not exercised in a browser (not verified).

## Findings (most severe first)

### 1. CRITICAL — "All Areas" on the Tally tab merges plots from different Areas
- **Where:** `script.js:963-976` (passes the whole project to `calculateForestryReport`), `forestry-calc.js:104-107` (plots counted by `plotNumber` only), same for `renderTallyCharts` (`script.js:1029` → `charts.js:144`).
- **What:** Plot 1 in Area A and plot 1 in Area B are counted as one plot, so every per-acre number on the All Areas summary cards and charts is divided by too few plots.
- **Scenario (verified):** One 20" tree in A-plot 1 and one in B-plot 1, BAF 10. Expected 2 plots, BA 10 sq ft/ac; actual: `numberOfPlots: 1`, `totalBaPerAcre: 20`, `totalVolPerAcre: 2063` (double). With Areas numbered 1..n each, All Areas overstates TPA/BA/BF by roughly the number of Areas.
- **Fix:** Count plots by `areaLetter + '|' + plotNumber` in `calculateForestryReport` (and `calculatePlotStats`), or have All Areas use the acre-weighted property summary instead.

### 2. CRITICAL — Work entered while IndexedDB failed to open is silently dropped on the next start
- **Where:** `storage.js:131-165` (`init`).
- **What:** If IndexedDB open fails or takes >4 s (slow phone, cold start), the session falls back to localStorage and every save goes there. On the next start IndexedDB opens, the `__idbMigratedFromLocalStorage` flag is already set, so the localStorage copies are never read again: trees entered in the fallback session disappear. The alert tells the user they are seeing an older copy but does not stop them entering new data that will be lost.
- **Scenario:** Phone is slow; open takes 4.5 s → fallback. Forester tallies 30 trees ("✓ Saved" shows). Next launch opens IndexedDB fine → those 30 trees are gone.
- **Fix:** Don't time out to a writable fallback when IndexedDB was used before (retry / block with a message), or on next IDB start merge any `tt3.*` localStorage records newer (by `updatedAt`) than IDB's.

### 3. IMPORTANT — Two tabs/windows overwrite each other's work (no cross-tab coordination)
- **Where:** `storage.js` cache (`readJSON`/`saveProject`/`getIndex`), `script.js:2364-2365` (save on `visibilitychange`/`pagehide`).
- **What:** Each tab holds its own in-memory cache and its own `currentProject`. Any save writes the whole project and the whole index from that tab's stale copy. Hiding a tab also saves.
- **Scenario:** Installed app and a browser tab open on the same project (Android/desktop share storage). Enter trees in window B; switch to window A and add one tree → A writes its `collectedData` (without B's trees) → B's trees lost. Same for the index: a project created in B vanishes from the list after A saves.
- **Fix:** `BroadcastChannel` / `storage` event to reload or lock (e.g. Web Locks "single writer" with a "open in another window" banner); at minimum compare `updatedAt` before writing.

### 4. IMPORTANT — Trees with more logs than the table allows get 0 board feet, silently
- **Where:** `script.js:604-605` (wheel offers 0.5–6 logs for every DBH > 10), `forestry-calc.js:31` (returns 0 when the key is missing).
- **What:** Tables stop at 3 logs (10–11"), 4 logs (12–19"), 5 logs (20–27"); e.g. a 16" tree at 4.5 logs, or 12" at 6 logs, has no entry.
- **Scenario (verified):** `getTreeVolume('12','6','Doyle')` = 0, `('16','4.5','Doyle')` = 0, `('18','5','Scribner')` = 0, `('20','6','International')` = 0. Volume/acre is understated with no warning. Also CSV imports (Match Columns clamps to 6).
- **Fix:** Limit the logs wheel / tap grid per DBH to the table's keys, or clamp to the largest key for that DBH, and add a Check Data warning.

### 5. IMPORTANT — Stored XSS from species names and imported entry fields
- **Where:** `script.js:903` (`<h3>${species}</h3>` in the tree tally), `script.js:726` (quick-pick label `${s}`), `script.js:804-817` (`plotNumber`, `areaLetter`, `cutStatus`, `ugsStatus` unescaped), `script.js:2469` (`err.message`).
- **What:** Species and entry fields come from CSV import, Match Columns, Merge and backup restore (`normalizeProject` keeps entry fields unvalidated) and reach `innerHTML` unescaped.
- **Scenario:** Import a CSV whose Species cell is `<img src=x onerror=alert(1)>` → opening the Tally tab runs it. The page can read/erase every project in storage.
- **Fix:** Use `escHtml` (already in script.js:1262) at those sinks; validate entries in `normalizeProject` (areaLetter /^[A-Z]$/, plotNumber int, cut/ugs Yes|No).

### 6. IMPORTANT — Multi-line tree notes break CSV round-trip (GPS lost on import/merge)
- **Where:** export `script.js:1181-1182` (notes quoted but newlines kept), import `script.js:1050` and `merge.js:33` (split on `\r?\n` before quote handling).
- **Scenario:** A tree note "Den tree\nmarked twice". Export ZIP, then Import CSV or Merge Another Device with it → row is cut at the newline; Notes truncated, Latitude/Longitude empty, second fragment dropped. (`csv-match.js` handles this correctly with `splitCsvRecords`.)
- **Fix:** Reuse csv-match's record splitter in both parsers, or replace newlines in notes on export.

### 7. IMPORTANT — Service worker install "succeeds" with an incomplete cache
- **Where:** `service-worker.js:60-73`.
- **What:** `.catch()` inside `waitUntil` swallows a failed `cache.addAll`, so the install resolves. Once the user taps Update, `activate` deletes the previous good cache, and the app is no longer usable offline.
- **Scenario:** One file 404s or the network drops mid-install (common in the field) → update bar shows → Update → offline launch fails.
- **Fix:** Re-throw in the catch (or drop the catch) so a failed install is discarded and the old version stays.

### 8. IMPORTANT — Safety copy reported as kept even when it was not (IndexedDB mode)
- **Where:** `storage.js:282-297` (`snapshot`), `storage.js:185-200` (`writeJSON` returns true before the IDB transaction completes).
- **What:** In IndexedDB mode `writeJSON` always returns true, so `snapshot()` returns true and the quota retry loop never runs; the destructive action (delete project, delete all, plot move) proceeds even if the copy failed to save.
- **Fix:** Make `snapshot` async and await the IDB write (expose a promise from `writeJSON`), and abort the destructive action if it fails.

### 9. MINOR — Backup reminder fires with no changes
- **Where:** `script.js:2364-2365` → `saveSessionData` → `Store.saveProject(p)` with `touch: true`; reminder test at `script.js:446`.
- **What:** Every screen lock / app switch bumps `updatedAt`, so a project backed up and only viewed counts as changed; it also reorders the project list.
- **Fix:** Save on hide with `{ touch: false }` (or only when something is dirty).

### 10. MINOR — First visit reloads the page
- **Where:** `script.js:41-42` with `service-worker.js` `clients.claim()`.
- **What:** On first install `controllerchange` fires (null → worker) and the page reloads, which can happen while the user is starting the tour or typing.
- **Fix:** Only reload if `navigator.serviceWorker.controller` was set at page load, or only after Update Now was tapped.

### 11. MINOR — CSV export does not escape quotes in Species
- **Where:** `script.js:1182`, tally block `script.js` ~1190, `forestry-calc.js:409,415`.
- **Scenario:** Species `Oak "big"` → malformed CSV row. Also values starting with `=`/`+` open as formulas in Excel.
- **Fix:** One `csvCell()` helper (double quotes; prefix `'` for leading `=+-@`).

### 12. MINOR — INVALID trees make the Stand Distribution TOTALS disagree with the summary
- **Where:** `forestry-calc.js:122-128`.
- **Scenario (verified):** A prism tree with no species: summary BA = 10, Stand Distribution TOTALS BA = 20.
- **Fix:** Leave invalid trees out of the BA totals, or add them to the summary too (pick one and note it in the CSV).

### 13. MINOR — Duplicated calculations that can drift
- `plot-export.js:37` computes BA with `0.005454154` and `trees × BAF` (counts trees with bad DBH) while everything else uses `BA_CONST = 0.005454` / `treeBaPerAcre`.
- "Plots needed" `ceil((2·CV/E)²)` is written twice: `script.js:861` and `charts.js:578`.
- **Fix:** Use `treeBaPerAcre` and one `plotsNeeded(cv, E)` in forestry-calc.js.

### 14. MINOR — Match Columns clamps plot numbers above 999 into plot 999
- **Where:** `csv-match.js:193,213`. Plots 1000+ are merged into one plot with no warning. Fix: skip with a count, or renumber.

### 15. MINOR — Stale leftovers
- `script.js:1, 2450, 2465` say "TimberTally v7" (the app is TimberTally 3).
- `script.js:1818` falls back to `./README.md`, which is not in the SW cache (offline 404) and shows raw markdown on GitHub Pages; `script.js:165` README_URL points at GitHub.
- `service-worker.js:150-160` large commented-out dynamic-cache block.
- `storage.js:392-393` two stacked doc comments for `saveFile`.
- `calculations_explained.html`, `csv_explained.html`, `proof_of_work.html` are redirect stubs not in the cache (only matter for old bookmarks).

### Unverified / methodology questions (not reported as defects)
- **Doyle form class scaling** (`forestry-calc.js:36`) is linear `vol × FC/78` (FC 86 = +10%). Published Mesavage–Girard tables change much more per form class point (roughly 3–4% per point for Doyle). Worth confirming against the source tables the user trusts.
- **plotNumber type:** `normalizeProject` does not coerce `plotNumber`; several places compare with `===` (`script.js:740, 1263`) and the report's `Set` would count `"1"` and `1` as two plots. If any old TimberTally 2 data stored plot numbers as strings this misbehaves; could not confirm TT2's format.
- **Recommendations from a hand-edited backup** without `title`/`text` would throw in `recommendations.js:135` (`esc` assumes a string). Only reachable with a non-app-made backup.
- Gingrich % uses N·QMD in place of ΣD (documented choice, consistent with the chart); not a bug.
- 375px layout and dark mode were not exercised in a browser.

Checked and fine: SW cache list matches every script/style/image/PDF referenced by index.html and code (except README.md above); cache cleanup is scoped to `timber-tally3-cache-` plus caches holding URLs under this scope; BOM headers parse (String.trim strips U+FEFF); tour targets all exist (two are created at runtime by plot-export.js / tour.js); restore only adds, never replaces; fixed-plot vs BAF expansion and the stratified property sampling error formula are correct.

## Recommendations for keeping future updates safe
1. **Calc golden tests** (node + vm, like calc-test.js): fixed fixtures for BAF and fixed plots, multi-Area with repeated plot numbers, empty plots, Cull, invalid trees, every DBH × logs choice the UI offers (assert volume > 0 for merchantable trees), and summary vs Stand Distribution TOTALS equality.
2. **CSV round-trip test:** export a project with quotes, commas and newlines in notes/species and GPS, re-import through all three parsers (Import, Match Columns, Merge) and assert identical entries.
3. **Storage tests** (fake-indexeddb): fallback-then-recover keeps data; snapshot failure blocks the destructive action; two "tabs" (two module instances on one DB) never lose a write.
4. **SW cache-list check:** a script that greps index.html and the JS for local file references and fails if any is missing from `urlsToCache` or missing on disk; also assert `CACHE_NAME` was bumped when shipped files changed.
5. **XSS lint:** a test that loads hostile strings (`<img onerror>`) as species/notes/area/project name through CSV and backup restore, renders every tab in jsdom and asserts no injected elements; plus a grep rule flagging `innerHTML` templates without `esc`.
